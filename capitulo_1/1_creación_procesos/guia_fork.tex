\section{Motivación}
En un sistema operativo moderno, los programas no siempre corren de forma aislada. A menudo, un programa necesita delegar tareas a otro proceso para realizarlas en paralelo o de forma independiente. En Linux/POSIX, la forma fundamental de crear un nuevo flujo de ejecución es ``duplicando'' el proceso actual.

\section{Idea Fundamental}
La función \texttt{fork()} crea un nuevo proceso (Hijo) que es una \textbf{copia exacta} del proceso que lo llamó (Padre). Ambos procesos continúan ejecutándose desde el mismo punto exacto (el retorno de \texttt{fork()}).

\section{Sintaxis Básica}
\begin{lstlisting}[numbers=none]
#include <unistd.h>
#include <sys/types.h>

pid_t pid = fork();
\end{lstlisting}

\section{Ejemplo Mínimo Funcional}
\begin{lstlisting}
#include <stdio.h>
#include <unistd.h>

int main() {
    pid_t pid = fork();

    if(pid < 0){
        perror("fork failed");
        return 1;
    }else if(pid == 0){
        printf("I am the child process!\n");
    }else{
        printf("I am the parent! My child's PID is %d\n", pid);
    }

    return 0;
}
\end{lstlisting}

\section{Explicación Paso a Paso}
\begin{enumerate}
    \item Se llama a \texttt{fork()}: el Sistema Operativo crea una copia del proceso.
    \item \textbf{Valor de retorno:} Es la clave para diferenciar quién es quién.
    \begin{itemize}
        \item Al \textbf{Padre} se le devuelve el PID del hijo (un número $> 0$).
        \item Al \textbf{Hijo} se le devuelve el valor \textbf{0}.
        \item Si hay error, devuelve $-1$.
    \end{itemize}
    \item A partir de la línea 6, ambos procesos corren el mismo código pero con valores de \texttt{pid} diferentes.
\end{enumerate}

\section{Qué ocurre en memoria (COW)}
Linux utiliza una técnica llamada \textbf{Copy-On-Write (COW)}. El proceso hijo comparte la misma memoria física que el padre hasta que alguno intenta \textbf{escribir} en ella. En ese instante, el Sistema Operativo duplica la página de memoria para que cada uno tenga su propia versión privada de los datos.

\section{Patrones comunes de uso}
El patrón \texttt{switch} es muy común cuando se tienen múltiples casos de error, hijo y padre:
\begin{lstlisting}
switch(fork()) {
    case -1: perror("error"); exit(1);
    case 0:  /* Codigo del hijo */ break;
    default: /* Codigo del padre */ break;
}
\end{lstlisting}

\section{Errores Comunes}
\begin{itemize}
    \item \textbf{Bomba lógica:} Hacer un \texttt{fork()} dentro de un bucle infinito sin control puede agotar los recursos del sistema (Fork Bomb).
    \item \textbf{Asumir orden:} El padre y el hijo corren de forma asíncrona. No puedes saber cuál imprimirá primero sin usar sincronización.
\end{itemize}

\section{Buenas Prácticas}
\begin{itemize}
    \item Siempre validar el retorno de \texttt{fork()}.
    \item Usar el tipo de dato \texttt{pid\_t} (definido en \texttt{sys/types.h}) para manejar Identificadores de Proceso.
\end{itemize}

\section{Ejercicios}
\begin{enumerate}
    \item Escriba un programa donde el hijo imprima los números del 1 al 5 y el padre los números del 6 al 10.
    \item Investigue qué sucede si un proceso hijo intenta modificar una variable global declarada antes del \texttt{fork()}. ¿Se modifica también para el padre?
\end{enumerate}
